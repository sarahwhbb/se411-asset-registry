# Backend

Spring Boot REST API for the SE411 Computer Asset Registry. It stores computers in an in-memory H2 database, so data is lost when the application stops. On every start `src/main/resources/data.sql` loads 6 sample computers.

## Requirements

- JDK 21 or later
- Maven 3.9 or later (the Maven wrapper in this folder needs to download its own Maven version, so a local `mvn` is simpler)

## Commands

Run these in this folder (`backend/`):

```bash
mvn spring-boot:run                          # start the API at http://localhost:8080
mvn test                                     # run all tests
mvn test -Dtest=AssetServiceTest             # one test class
mvn test -Dtest=AssetServiceTest#getThrowsWhenMissing   # one test method
```

If startup fails with "Port 8080 was already in use", stop the other process on that port first. The frontend expects the API on port 8080.

## REST API

Base URL `http://localhost:8080/api/assets`. CORS allows `http://localhost:5173` (the Vite dev server).

| Method | Route | Purpose | Success | Errors |
|---|---|---|---|---|
| POST | `/api/assets` | add a computer | 201 + saved asset | |
| GET | `/api/assets/{id}` | find by id | 200 | 404 |
| GET | `/api/assets?page=&size=` | paginated list (Spring `Page`), defaults `page=0`, `size=10` | 200 | |
| PUT | `/api/assets/{id}` | update | 200 + saved asset | 404 |
| DELETE | `/api/assets/{id}` | delete | 204 | 404 |

DELETE goes beyond the four routes in the course brief; it is there so the frontend delete feature works.

The id always comes from the URL (PUT) or the database (POST); an `id` in the request body is ignored.

### Computer JSON

Field names match the frontend exactly.

```json
{
  "id": 1,
  "assetTag": "PC-0001",
  "brand": "Dell",
  "model": "Latitude",
  "serialNumber": "S1",
  "purchaseDate": "2024-01-01",
  "status": "In use",
  "assignedTo": "Sara",
  "price": 1000.0
}
```

`status` is one of In use, In stock, Repair, Retired. `purchaseDate` is `YYYY-MM-DD`. `price` is in SAR. The list response looks like `{ "content": [ ...computers ], "totalPages": 1, ... }`.

The backend does not validate the data (required fields, unique asset tag, future dates, price above 0); the frontend form does.

Try it with curl:

```bash
curl -X POST http://localhost:8080/api/assets -H "Content-Type: application/json" \
  -d '{"assetTag":"PC-0001","brand":"Dell","model":"Latitude","serialNumber":"S1","purchaseDate":"2024-01-01","status":"In use","assignedTo":"Sara","price":1000}'
curl "http://localhost:8080/api/assets?page=0&size=10"
```

## Structure

`src/main/java/edu/psu/se411/backend/`:

| Class | Responsibility |
|---|---|
| `Asset` | JPA entity; `id` is generated by the database |
| `AssetRepository` | `JpaRepository<Asset, Long>` |
| `AssetService` | create, get, list, update, delete; throws `AssetNotFoundException` for an unknown id |
| `AssetNotFoundException` | `@ResponseStatus(NOT_FOUND)`, so the API answers 404 |
| `AssetController` | the routes above, with `@CrossOrigin` for the frontend |

```
AssetController → AssetService → AssetRepository → H2
```

## Tests

`src/test/java/edu/psu/se411/backend/`:

| File | Covers |
|---|---|
| `AssetServiceTest` | JUnit + Mockito with the repository mocked: create, get, list, update, delete and the not-found cases |
| `AssetControllerTest` | `@WebMvcTest` + MockMvc with the service mocked: every route, status codes, the `Page` JSON and the CORS header |
| `BackendApplicationTests` | the application context starts |
