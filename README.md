# SE411 Computer Asset Registry

SE411 (Fall 2026-27) team project: a web app for managing a company's computers (add, view, edit, delete).

- **Part 1:** React frontend (`frontend/`).
- **Part 2:** Spring Boot REST API with an H2 database (`backend/`), integrated with the frontend.

## Features

- Home page with asset counts by status
- Menu on every page: Home, Computers, Add Computer, About
- List all computers with status badges
- Add and edit computers with form validation (required fields, unique asset tag, no future purchase date, price above 0)
- Delete with confirmation
- About page with the team members
- Responsive layout (table on wide screens, cards on narrow ones)

## Tech stack

- **Frontend:** React 19, Vite, React Router, Vitest + React Testing Library, oxlint.
- **Backend:** Java 21, Spring Boot 4, Spring Web, Spring Data JPA, H2 (in-memory), Maven, JUnit + Mockito.

## Getting started

Requires Node.js 22.12 or later (Node 24 LTS recommended), npm, JDK 21 or later and Maven.

Start the backend first, then the frontend (two terminals):

```bash
git clone https://github.com/sarahwhbb/se411-asset-registry.git
cd se411-asset-registry

# Terminal 1: backend at http://localhost:8080
cd backend
mvn spring-boot:run

# Terminal 2: frontend at http://localhost:5173
cd frontend
npm install
npm run dev
```

The database is in-memory H2, so data is lost when the backend stops. `backend/src/main/resources/data.sql` loads 6 sample computers on every start.

Other scripts:

```bash
npm test         # frontend tests (in frontend/)
npm run lint     # lint the frontend
npm run build    # production build into frontend/dist/
mvn test         # backend tests (in backend/)
```

## REST API

Base URL `http://localhost:8080/api/assets` (CORS allows `http://localhost:5173`).

| Method | Route | Purpose |
|---|---|---|
| POST | `/api/assets` | add a computer (201) |
| GET | `/api/assets/{id}` | find by id (404 if missing) |
| GET | `/api/assets?page=&size=` | paginated list (Spring `Page`, defaults page 0, size 10) |
| PUT | `/api/assets/{id}` | update (404 if missing) |
| DELETE | `/api/assets/{id}` | delete (204, 404 if missing) |

## Backend

The backend (`backend/`) is a Spring Boot application that stores the computers in an in-memory H2 database and exposes them through the REST API above. The frontend calls it with `fetch`; see [backend/README.md](backend/README.md) for commands and details.

Requests flow through four layers:

```
AssetController  →  AssetService  →  AssetRepository  →  H2
 (REST, JSON)        (logic, 404s)    (Spring Data JPA)
```

- **`Asset`** is the JPA entity. Its fields match the frontend exactly (see Computer fields below); the database generates the `id`.
- **`AssetRepository`** extends `JpaRepository<Asset, Long>`, which provides save, find, paged find and delete without extra code.
- **`AssetService`** holds the logic. Unknown ids throw `AssetNotFoundException`, which Spring turns into an HTTP 404.
- **`AssetController`** maps the five routes. The list route builds a page from the `page` and `size` parameters and returns a Spring `Page`, so the frontend reads `.content`. `@CrossOrigin` allows the Vite dev server at `http://localhost:5173`.

Notes:

- Data is lost when the backend stops, and the 6 sample computers in `data.sql` are reloaded on every start.
- The backend validates POST and PUT bodies with Bean Validation (required text fields, purchase date required and not in the future, valid status, price above 0) and answers 400 on bad input. The unique asset tag check happens in the frontend form only.
- `DELETE /api/assets/{id}` goes beyond the four routes in the course brief; it is there so the frontend delete feature works.

Tests (`mvn test` in `backend/`): a JUnit + Mockito test for `AssetService` with the repository mocked, and a `@WebMvcTest` + MockMvc test for `AssetController` with the service mocked.

## Computer fields

`id` (generated by the backend), `assetTag`, `brand`, `model`, `serialNumber`, `purchaseDate`, `status` (In use / In stock / Repair / Retired), `assignedTo`, `price` (SAR).
